## 2) إجراءات منجزة

1. إنشاء مشروع Vercel باسم `pt650` في فريق إمدادات وتهيئته `framework=vite`, `rootDirectory=frontend`, `outputDirectory=dist`, `installCommand=npm ci`, `buildCommand=npm run build`, `nodeVersion=22.x`.
2. استخدام `VITE_DEMO=1` لمطابقة سلوك نشر GitHub Pages القائم في الوظائف التي تحتاج Legacy Node backend. هذا ليس تفعيلاً تجريبياً لخدمات المصادقة المرتبطة بـ PT650.
3. التحقق من اكتمال بناء Vercel بحالة `READY`. لا يُعد ذلك اختبار E2E للمستخدمين.
4. قصر حماية Vercel Authentication على Preview في مشروع `pt650` الجديد دون المساس بالموقع القديم.
5. إنشاء الفرع `pt650/standalone-migration` لإعداد الهوية المستقلة دون تغيير فرع الإنتاج `main`.
6. تحديث الاسم الداخلي لـ `frontend/package.json` و`frontend/package-lock.json` من `opengym-frontend` إلى `pt650-web` ضمن فرع الترحيل.
7. تغيير `appName` الظاهر في Capacitor إلى PT650 مع الاحتفاظ **عمدًا** بـ `appId=ch.duartesantos.opengym` لتجنب كسر ترقية تطبيقات الجوال الحالية قبل تصميم انتقال متجر التطبيقات.
8. إنشاء README خاصة بـ PT650، مع نسخ README الموروثة إلى `docs/OPENGYM_UPSTREAM_README.md` وتثبيت بيان اشتقاق المشروع والترخيص.

## 3) ما لا يجوز كسره أثناء الفصل

- لا تغيير لقواعد بيانات Supabase، ولا نقل للمستخدمين أو RLS أو Edge Functions بدون فحص قبول مستقل.
- جلسات `localStorage` مرتبطة بأصل (origin) الموقع؛ عند الانتقال إلى نطاق جديد يحتاج المستخدم غالبًا إلى تسجيل دخول جديد، مع بقاء حسابه وبياناته على Supabase.
- لا تحذف أو تؤرشف المستودع القديم، ولا تعيد توجيه رابط GitHub Pages، ولا تنقل نطاقًا مفوضًا قبل نجاح الاختبارات على البديل.
- لا تفعّل الحركات/التمارين أو الوسائط التي سبق إيقاف نشرها أثناء ترحيل البنية.
- لا تغيّر `appId` أو بيانات Apple/Google mobile IDs تلقائيًا. يجب التنسيق مع خطة ترقية مستقلة.
- لا ترفع `.env` أو ملفات أسرار إلى المستودع الجديد.
- لا تُزل ملفات `LICENSE` أو `NOTICE.md` أو إشعارات الاعتماديات المحمية.

## 4) خطوة مستودع GitHub الباقية (إجراء حسابي)

أداة GitHub المتصلة متاحة لإنشاء الفروع والملفات وPR، لكنها **لا تتيح إنشاء مستودع جديد أو إلغاء صفة fork برمجيًا**. يتطلب الفصل الحقيقي من واجهة GitHub إنشاء مستودع عام مستقل باسم `pt650` في حساب `alalmaiesa-glitch` (ليس `Fork`). بعد إنشاء المستودع:

1. انسخ المحتوى من الفرع الجاهز `pt650/standalone-migration` إلى المستودع المستقل مع الملفات والحقوق اللازمة؛ يفضّل **لقطة مصدر نظيفة** بدل جلب كل سجل Git التاريخي غير المدقق.
2. تأكد من `LICENSE` و`NOTICE.md` ومراجع المصدر الأصلي في النسخة الجديدة، وأبقِ الشيفرة المشتقة متاحة وفق AGPL.
3. نفّذ `npm ci`, `npm test`, `npm run build` من `frontend`.
4. أجرِ كشف أسرار Gitleaks على المستودع الجديد وتحقق من سلامة الاعتماديات.
5. أعد ربط مشروع Vercel `pt650` بالمستودع الجديد والفرع `main`، وانشر مجددًا ثم اختبر تسجيل الحساب وتسجيل الدخول وخروج المستخدم، حماية المسارات، وظائف Supabase وبيانات التقدم والواجهات باللغة العربية.
6. بعد نجاح فحص الاستخدام الفعلي، حدّث الرابط القانوني لخدمة المصدر، وقرر تأكيد وقف GitHub Pages القديم أو إبقاء إعادة توجيه مفيدة.
